# Known Limitations — One User, One Agent

This document outlines intentional architectural boundaries, trade-offs, and features left incomplete on purpose to focus on the core evaluation criteria: **goal-directed decisions, evidentiary rigor, real-time safety verification, and honest measurement.**

---

## 1. Single-Node In-Memory / SQLite Persistence
- **Current State**: Viewer facts, decisions, and outcomes are persisted in a local SQLite database (`agent_state.db`) with periodic JSON export.
- **Why It Was Scoped This Way**: SQLite is part of the Python standard library, requires zero external services or daemon setup for evaluators, provides ACID transaction guarantees, and handles the synthetic dataset (5,000 users, 2,769 triggers) in under 20 milliseconds per transaction.
- **Production Path to 10M Viewers**:
  - In production with 10M viewers across 40 dialects, SQLite would be replaced by a low-latency partitioned key-value / document store (e.g., **Aerospike, Redis, or DynamoDB**) for active viewer state and facts.
  - Event ingestion would be decoupled via a distributed log (**Apache Kafka or AWS Kinesis**), with agents horizontally scaled across a stateless worker cluster partitioned by `user_id` hashing.

---

## 2. Mock Model Provider vs Live External LLM API
- **Current State**: The system defaults to `src/model/mock_provider.py`, which provides deterministic model simulation, fault injection (timeouts, HTTP 503, malformed JSON), and structured decision generation without external API keys.
- **Why It Was Scoped This Way**: Evaluators must be able to clone and run the repository instantly without requiring personal API keys, cloud billing, or network access.
- **Production Path**:
  - The provider interface is modular. Plugging in live hosted models (e.g. Anthropic Claude 3.5 Sonnet, OpenAI GPT-4o, Google Gemini 1.5 Pro) requires only implementing an adapter adhering to the `ModelProvider` abstract base class with exponential backoff and circuit-breaking.

---

## 3. Statistical Power for Low-Frequency Goals
- **Current State**: In the 2,769 replay triggers, certain goals occur infrequently. For example, Goal `G04` (`trial_to_paid_7d`) had only 1 eligible viewer during the single replay day.
- **Why It Was Scoped This Way**: The replay dataset covers a single synthetic calendar day (October 1, 2026). Rare transition events naturally appear in small numbers over a 24-hour window.
- **Honest Handling**: Rather than fabricating conversion numbers, the impact report honestly displays `N=1`, `Success=0`, and notes wide confidence intervals for low-frequency goals.

---

## 4. External Channel Delivery Webhooks
- **Current State**: Push notifications and WhatsApp messages are published to `sample_run/actions.jsonl` and fed into `simulator/simulate_outcomes.py`.
- **Why It Was Scoped This Way**: Live delivery to Firebase Cloud Messaging (FCM), Apple Push Notification service (APNs), or WhatsApp Business Cloud API requires live client apps and registered carrier gateways, which are outside the scope of an offline synthetic challenge.
- **Safety Enforcement**: Even without live gateways, all messaging constraints (quiet hours 22:00–08:00 IST, opt-in consent, frequency caps of 1/day, and WhatsApp template variable validation) are 100% verified and enforced by the independent Verifier.

---

## 5. TV App Signal Scarcity (`G11`)
- **Current State**: Goal `G11` (`tv_activation_7d`) is evaluated, but in the synthetic event stream, `tv_app_open` events are rarely generated by the simulator.
- **Why It Was Scoped This Way**: The synthetic data generator produces fewer TV-specific events. The outcome judge attributes `inconclusive` when the 7-day observation window elapses without positive or negative attributable signals.

---

## 6. Advanced Recommender Re-Ranking
- **Current State**: Title recommendations within the chosen dialect rely on business heuristics (new releases, popular in dialect, watch history affinity) rather than heavy neural collaborative filtering.
- **Why It Was Scoped This Way**: The assignment brief explicitly states:
  > *"This challenge rewards judgment, evidence, timeliness and honest measurement. A clever recommender without a trustworthy decide, act and measure loop will not score well."*
  
  Engineering effort was deliberately directed into the decide-act-verify-measure loop, conflict resolution, and fault recovery.
